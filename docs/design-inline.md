# 設計案：インラインコメントと自動Resolved（未実装）

状態：案。今回の75試行の比較には含めない。記事では「発展」として触れる（D-28）。

## 目的
コードの問題は、PRの会話欄のコメントではなく、差分の該当行へのインラインコメントにする。
後続のコミットで直ったら、そのスレッドを自動でResolvedにする。

## 流れ
1. **指摘の候補（AI）**：`result.json`に、`findings: [{path, line, message}]`を足す（最大5件）。AIは書き込まない。
2. **検証と投稿（スクリプト）**：`post.sh`が、各findingを検証し、通ったものだけを、PRのレビューコメント（`POST /pulls/{n}/comments`、`commit_id`は、PRのhead）にする。
   - `path`は、PRの差分にあるファイルである。
   - `line`は、差分の右側（変更後）に出る行である。
   - `message`は、AIの欄と同じ無害化を通す（D-18）。
   - 通らない指摘は、捨てずに、従来のPRコメントの本文に載せる。
3. **重複の防止**：各コメントの先頭に、`<!-- triage:inline path=… line=… cat=… -->`を入れる。同じ印が、未解決のスレッドにあれば、新しく作らない。
4. **自動Resolved（スクリプトのみ。AIなし）**：CIが成功した実行を契機に、次の条件をすべて満たすスレッドを、GraphQLの`resolveReviewThread`で閉じる。
   - スレッドの最初のコメントが、このボットの印を持つ。
   - GitHubが`isOutdated: true`と判定している（指摘した行が、後続のコミットで変わった）。
   - 契機のCI成功が、そのPRのhead（指摘より後のコミット）である。

## 決めたこと
- 閉じる条件は、「CI成功」かつ「指摘の行が変更された」。CIが成功しただけでは、閉じない（無関係な修正で閉じるのを避ける）。
- 指摘の内容は、AIが候補を出し、スクリプトが検証する。
- 人がResolvedにしたスレッドを、開き直さない。人がUnresolvedにしたスレッドを、自動で閉じない（ボットの印があっても、人の操作が後なら、触らない）。

## 必要な変更
- 権限：`pull-requests: write`（現在のワークフローが持つ範囲で足りるか確認する）。
- 契機：現在のゲートは、失敗の実行だけが対象。成功した実行にも反応する、Resolved専用の入口が要る（別ワークフロー）。
- スキーマ：`result.schema.json`に`findings`を足す。テスト：検証の通過と棄却、重複、Resolvedの条件。

## 限界
- `isOutdated`は、行が変わったことしか示さない。直った証明ではない（CI成功との組み合わせで補う）。
- 差分の外の行（変更していないファイルの問題）には、インラインコメントを付けられない。従来のPRコメントに載せる。
- ボットの身元は、`github-actions[bot]`で共通（既知の限界）。
